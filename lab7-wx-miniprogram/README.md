# 校园报修助手·小程序

> 《移动应用开发》综合项目（实验七）
> 选题方向：项目九·微信小程序应用 —— 校园报修
> 作者：李春雨（学号 202305567128，计科 2 班）

## 一、做什么 / 为什么做

面向校园宿舍、教室、公共区域的报修场景，开发一个让师生「随手提交报修、跟进处理进度」的微信小程序。

核心痛点：
- 传统报修需到宿管处登记、电话沟通，记录易丢失；
- 维修进度不透明，无法及时反馈；
- 管理员缺少集中处理入口，统计不便。

本方案用小程序轻量化解决：扫码即用、提交即存、处理即通知。

## 二、核心功能

| 页面 | 路径 | 职责 |
| --- | --- | --- |
| 报修列表 | `pages/index/index` | 按状态（未处理/已处理）+ 楼栋筛选，分页加载，点击进详情 |
| 提交报修 | `pages/publish/publish` | 表单录入（位置/楼栋/房间/手机/故障类型/描述/图片）+ 输入校验 + 订阅消息 |
| 报修详情 | `pages/detail/detail` | 查看单条记录、预览图片、一键拨号/复制电话 |
| 管理后台 | `pages/admin/admin` | 仅管理员可见，处理/删除报修、发送处理完成通知 |

业务流程：`提交报修 → 写库 → 通知管理员 → 管理员处理 → 通知报修人 → 列表状态更新`

## 三、技术架构

```
┌─────────────────────────────────────────────┐
│  UI 层（Page）  index / publish / detail / admin   │
├─────────────────────────────────────────────┤
│  Repository 层  utils/api.js（统一封装）              │
├──────────────┬──────────────────────────────┤
│  云开发优先    │  本地兜底（实验七新增）              │
│  - 云数据库    │  - wx.storage 本地缓存             │
│  - 云函数     │  - mock 种子数据                │
│  - 云存储     │  - 「我的报修」离线缓存           │
└──────────────┴──────────────────────────────┘
```

**关键设计**：

1. **统一 Repository 层**：所有数据访问走 `utils/api.js`，页面不直接调 `wx.cloud`，方便维护与切换数据源。
2. **云开发 + 本地兜底双模**（实验七完善）：`USE_MOCK_FALLBACK=true` 时，未开通云环境或调用失败自动回退到 `wx.storage` 本地数据，保证无云环境也能演示完整业务流程。
3. **本地数据保存**（任务书要求）：提交的报修同步写入 `wx.storage` 的 `my_repairs` 缓存，支持离线查看本人提交记录；管理员信息缓存到 `admin`。
4. **输入校验**：申报人/位置/楼栋/房间/故障类型/手机号正则/描述均校验，缺项给 Toast 提示。
5. **异常处理**：所有云调用 `try/catch`，失败时给用户明确 Toast 反馈，不再只 `console.log`。
6. **订阅消息通知**：提交报修给管理员发「新报修」通知，处理完成给报修人发「已处理」通知（云函数）。
7. **角色权限**：`c_role` 集合存管理员 openid，前端按 openid 判断是否显示「管理」入口。

## 四、运行方式

### 方式一：有云开发环境（完整功能）

1. 微信开发者工具导入 `d:\rain_android\wx`；
2. 修改 `miniprogram/config/index.js` 中 `CLOUD_ENV` 为你的云环境 ID；
3. 上传 `cloudfunctions/` 下的 `login`、`applyNotice`、`handleNotice` 云函数（上传并部署，不上传 node_modules）；
4. 云控制台创建集合 `c_apply` / `c_role` / `c_share`，导入 `databases/` 下的数据；
5. `c_apply` 集合权限改为「自定义安全规则」read/write true；
6. 编译运行，控制台输出 openid，替换到 `c_role` 集合即可获得管理员权限。

### 方式二：无云环境（本地兜底演示，实验七新增）

无需开通云开发，直接编译即可运行：
- `api.js` 检测到 `wx.cloud` 不可用或调用失败，自动回退到本地 `wx.storage`；
- 首次启动注入 3 条 mock 种子数据（2 条未处理 + 1 条已处理）；
- 提交的报修写入本地 `my_repairs` 缓存；
- 管理员、登录、订阅消息均走 mock，不影响主流程演示。

> 适合答辩演示、本地开发、无云配额场景。

## 七、测试说明

### 边界与异常用例

| 场景 | 预期 | 实测 |
| --- | --- | --- |
| 列表为空 | 显示空状态 | mock 种子 3 条，切换「已处理」可见 1 条 |
| 无云环境 | 自动本地兜底，不报错 | 关闭云开发即可验证 |
| 提交缺申报人 | Toast「请填写申报人」 | validate() 拦截 |
| 手机号格式错 | Toast「请填写正确手机号」 | 正则 `/[1][3,4,5,7,8][0-9]{9}$/` |
| 图片超 6 张 | Toast「最多上传 6 张」 | chooseImage remaining 校验 |
| 加载失败 | Toast「加载失败，请重试」 | 断网/云函数异常 |
| 详情不存在 | Toast「记录不存在或已删除」 | 删除后回退详情页 |
| 非管理员点管理 | Toast「暂无权限」 | isAdmin 判断 |

### 演示步骤（答辩用）

1. 首页：切「未处理/已处理」Tab，切楼栋筛选，触底分页；
2. 提交报修：填表 + 选图 + 提交，回到首页见新记录；
3. 详情页：预览图片、拨号、复制电话；
4. 管理后台：处理一条（状态变「已处理」）、删除一条；
5. 无云演示：关闭云开发，重启小程序，验证本地兜底正常。

## 十、答辩四问自检

- **数据在哪里？** 云数据库 `c_apply` + 本地 `wx.storage`（my_repairs/mock_seeded/admin）。
- **状态在哪里？** Page 的 `data` + `setData`；全局在 `App` 与 `wx.storage`。
- **事件从哪里来、到哪里去？** 用户操作 → Page 方法 → `api.js` → 云/本地 → 回调 `setData` 渲染。
- **错误在哪里处理？** `api.js` 每个方法 `try/catch` + 页面 Toast 反馈，云失败自动回退本地。
